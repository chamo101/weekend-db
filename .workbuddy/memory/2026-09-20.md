## 2026-09-20 · 共建表「有 141 行但没数据」修复（第二起，链接修好后紧接发生）

**症状**：大人刷新链接后追问「链接文档是存在了 没数据啊里面？？」

**结论：文档里确实没有数据——141 行是空壳行（有行、有 record_id、没有字段值）。9/9 的"141条分5批写入"只创建了行，字段值从未真正写进去。**

**诊断关键（这次差点又判断错）**
- `list_records` 全量列举返回 `{"field_values":[],"record_id":"ry7xS7"}` —— 每行值都是空数组
- 一度怀疑"数据在、只是读不出来"。**决定性检验是：按 `record_ids` 精确读取时能读到值**
  → 说明读取通道正常（我临时写的一条测试记录 `riMOYA` 能完整读回），旧行读不到 = 旧行真的空
- 再验一次：旧记录按 record_id 单读，`field_values` 数量 = 0 ✅

**根因**：`smartsheet.list_records` **不带 `record_ids` 时，全量列举返回的 `field_values` 一律是空数组**，只有 `total` 准。
我上午报的「141 条一条不少」是被 `total=141` 骗了——那是行数，不是数据。

**修复方式：`update_records` 把 141 个空行按序填值（零删除、行数不变）**
- 先备份 record_id 清单 → `.backup/record_ids_before_fix.json`（142 个，含我加的测试记录）
- 试写 3 条 → 按 record_ids 读回 → **顺序完全对齐**（第1条=亚马逊北京、第2=亚马逊上海、第3=苹果北京），证明空行顺序就是 CSV 顺序
- 分 5 批（30+30+30+30+18）补齐剩余 138 条，每批间隔 0.8s，全部 OK
- 删掉测试记录 `riMOYA`，`total` 回到 141
- 全量回读校验：**141/141 有值，0 条空行，0 条与 CSV 不符**
- 字段映射：源数据「官方/媒体公开报道」「媒体报道」→ 表格选项「官方或媒体报道」（表格选项只有 官方或媒体报道/企业信息平台/个人经历）

**独立验证（最后一道）**：`manage.export_file` 导出成 xlsx 再解析 ——
双休公司数据主表 **141 行 × 13 列**，数据完整。其余三张表 0 行（本就该空，还没人用小程序提交）。

**连带修 bug：同步脚本一直是瞎的**（commit `b765482`）
- `fetch_all()` 用全量 `list_records` 读取 → 永远拿到空值 → 每条因缺 `company` 被 `continue` → 稳定输出「141 条，新增 0 条」，**看起来完全正常**
- 改为两步：先分页取 `record_id`，再按 `record_ids` 分批（≤40）读值；`_flatten()` 正确解析 `text_value`/`option_value`/`computed_value`
- 修正分页游标 `next_offset` → **`next`**（原代码参数名就是错的）
- 新增告警：**"记录数正常但字段值全空"直接 stderr 报错**，杜绝再次静默
- 修复后实测：`共建表记录: 141 条（其中有值 141 条）` ✅

**遗留风险（未修，上线前必看）**
`miniprogram/cloudfunctions/tdocProxy/index.js` 走的是腾讯文档**开放平台 OpenAPI**（`docs.qq.com/openapi/v2/smart/sheet/...`），
用的是 `r.company`/`r.city`/`{records:[{company,...}]}` 这类**英文字段名**，而表格字段是中文标题（公司名称/城市/讨论内容…），
两边对不上。云函数尚未部署（README 里 5 项上线待办未做），**部署前必须先实测读写链路**，否则会重复"静默写空"的坑。

**教训**
1. `total` 只代表行数。判断智能表有没有数据，**必须按 `record_id` 抽读字段值**。
2. 无登录态的浏览器截图不能当判据——游客态只加载工具栏和列头，数据不渲染。
3. 一个智能表文档下有多个子表，**默认打开的是第一张**。「公司讨论区」是空的容易让人误判整个文档没数据。
4. 排查方法已固化为 skill `tencent-docs-smartsheet-data`。
